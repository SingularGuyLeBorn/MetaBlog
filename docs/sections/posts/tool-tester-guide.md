# 工具测试平台使用指南

## 简介

工具测试平台（ToolTester）是一个可视化界面，用于测试和验证 AI Agent 的所有工具功能。它支持单个工具测试和批量测试，帮助开发者快速发现和修复工具问题。

## 访问方式

访问路径：`/sections/posts/tool-tester`

或在浏览器中直接访问：`http://localhost:5173/sections/posts/tool-tester`

## 界面说明

### 1. 工具列表（左侧）

工具按类别分组展示：

| 类别 | 图标 | 工具数量 |
|------|------|----------|
| 知识库文章 | 📚 | 6 |
| 知识库管理 | 🗄️ | 7 |
| 网络内容抓取 | 🌐 | 8 |
| 系统工具 | 🛠️ | 2 |
| 文本处理 | 📝 | 2 |

点击工具名称即可选中，选中后显示参数配置面板。

### 2. 参数配置（中间）

支持两种模式编辑参数：

**表单模式** - 可视化输入框
- 字符串输入框
- 数字输入框
- 布尔值开关
- 数组文本框（每行一个值）

**JSON 模式** - 直接编辑 JSON
- 点击「JSON 模式」开关切换
- 支持复杂嵌套参数
- 实时语法检查

### 3. 执行结果（右侧）

**执行结果标签页**
- 显示工具执行的成功/失败状态
- 格式化显示返回结果（字符串或 JSON）
- 批量测试时显示测试报告统计

**执行日志标签页**
- 实时显示执行过程
- 记录每次工具调用的详细信息
- 包含时间戳和日志级别

## 功能使用

### 单工具测试

1. 从左侧选择要测试的工具
2. 填写参数（必填项带 * 号）
3. 点击「▶ 执行工具」按钮
4. 在右侧查看执行结果和日志

示例：测试 `test_echo`
```
message: "Hello World"
repeat_count: 3
```

### 批量测试所有工具

1. 点击顶部「🚀 测试所有工具」按钮
2. 等待批量执行完成（会依次测试所有可用工具）
3. 查看测试报告：
   - 总计测试数量
   - 成功数量
   - 失败数量
   - 成功率百分比
   - 每个工具的详细结果

## 测试报告解读

批量测试完成后，会显示如下统计信息：

```
📊 测试报告

总计: 25    成功: 20    失败: 5    成功率: 80%

详细结果:
✅ test_echo (45ms)
✅ get_current_time (12ms)
❌ web_search - HTTP 错误: 429
✅ github_get_repo (234ms)
...
```

### 常见状态说明

| 状态 | 含义 | 处理方式 |
|------|------|----------|
| ✅ 成功 | 工具执行正常 | 无需处理 |
| ❌ 失败 | 工具执行出错 | 查看错误信息，修复工具 |
| ⏱ 超时 | 执行时间过长 | 检查网络或工具性能 |

## 开发者指南

### 添加新工具后如何测试

1. 在 `definitions.ts` 中定义工具 schema
2. 在 `executors-legacy.ts` 中实现工具逻辑
3. 在 `index.ts` 中注册工具
4. 刷新工具测试平台页面
5. 在工具列表中找到新工具并测试

### 调试工具问题

1. 打开浏览器开发者工具（F12）
2. 切换到 Network 面板
3. 执行工具，观察 API 请求和响应
4. 查看 Console 面板中的日志输出

### 工具状态标记

在 ToolTester 的工具列表中，工具状态由 `ToolDefinition` 中的 `status` 字段控制：

| 状态 | 颜色 | 说明 |
|------|------|------|
| available | 🟢 绿色 | 工具可用，可以测试 |
| developing | 🟡 黄色 | 开发中，暂时不可用 |
| deprecated | ⚪ 灰色 | 已弃用，不建议使用 |

## 注意事项

1. **网络工具限制**：部分网络工具（如 web_search）可能受 API 速率限制
2. **GitHub 限制**：未认证请求每小时限制 60 次
3. **ArXiv 限制**：请求过于频繁会被暂时封禁
4. **文件操作**：测试文件工具时注意不要删除重要文件
5. **数据丢失**：Knowledge Base 目前使用内存存储，刷新页面数据会丢失

## 问题反馈

如果在使用工具测试平台时遇到问题：

1. 查看浏览器控制台的错误信息
2. 检查网络连接是否正常
3. 确认工具参数是否正确
4. 在 GitHub Issues 中提交问题报告
