# Agent 系统

MetaBlog 的 Agent 系统让你可以创建多个具有不同能力和角色的 AI Agent，每个 Agent 拥有独立的工具集、提示词和会话历史。

---

## 🤖 核心概念

### Agent

一个 Agent 是 AI 的完整配置单元，包含：

| 属性 | 说明 |
|------|------|
| **名称** | Agent 的显示名称 |
| **系统提示词** | 定义 Agent 的角色和行为 |
| **模型** | 使用的 AI 模型（DeepSeek / Kimi 等） |
| **温度** | 创意程度（0-2） |
| **可用工具** | Agent 可以调用的工具集合 |
| **Skill** | 预设的能力组合 |

### Skill

Skill 是预定义的工具组合和提示词模板，让 Agent 快速获得特定领域的能力：

| Skill | 描述 | 包含工具 |
|-------|------|---------|
| 通用助手 | 默认对话模式 | 基础工具 |
| 写作专家 | 文章创作和编辑 | 文章管理 + 文本处理 |
| 编程助手 | 代码编写 + GitHub | 代码工具 + GitHub 全套 |
| 数据分析师 | 数据分析 + 报告 | 分析工具 + 文章管理 |
| 创意助手 | 头脑风暴 + 灵感 | 创意工具 + 知识管理 |

### 会话

每个 Agent 拥有独立的会话历史，支持：
- 多轮对话上下文
- 消息版本管理（重新生成并切换）
- 会话重命名和删除

## ⚙️ 配置模式

创建 Agent 时有四种配置模式：

### 1. 纯提示词模式

完全通过自定义系统提示词定义 Agent 角色。适合简单的问答型 Agent。

```
系统提示词：你是一位资深的 Python 技术专家，擅长解答编程问题...
工具：全部可用
```

### 2. 纯技能模式

选择预设的 Skill，自动加载对应的工具和提示词。适合快速创建专业 Agent。

```
Skill：写作专家
→ 自动加载文章管理工具 + 文本处理工具
→ 自动应用写作专家提示词模板
```

### 3. 纯工具模式

手动选择 Agent 可用的工具。适合精细控制权限。

```
工具选择：
☑ create_article    ☑ update_article
☑ web_search        ☑ execute_code
☐ feishu_doc_create ☐ yuque_doc_create
```

### 4. 混合模式

Skill + 额外工具扩展。最灵活的配置方式。

```
Skill：编程助手
额外工具：feishu_doc_create, feishu_im_send
→ 编程助手能力 + 飞书文档/消息能力
```

## 🎛️ Agent 面板使用

访问 `/chat` 页面的 Agent 面板，可以进行以下操作：

### 创建 Agent

1. 点击"新建 Agent"
2. 输入名称和描述
3. 选择配置模式
4. 配置模型、温度、提示词和工具
5. 保存

### 编辑 Agent

1. 在 Agent 列表中选择要编辑的 Agent
2. 修改配置项
3. 保存（实时生效）

### 切换 Agent

1. 在聊天界面顶部选择 Agent
2. 新会话会使用选中的 Agent 配置
3. 每个 Agent 的会话历史相互独立

## 🧩 Skill 开发

### Skill 目录结构

```
.skills/
├── <skill-name>/
│   ├── SKILL.md           # Skill 定义文件
│   └── ...                # 其他资源
```

### SKILL.md 格式

```markdown
# Skill 名称

## 描述
一句话描述这个 Skill 的用途。

## 系统提示词
```
你是一位...（详细的角色定义）
```

## 工具列表
- tool_name_1
- tool_name_2
- tool_name_3

## 使用场景
1. 场景描述...
2. 场景描述...
```

### 开发步骤

1. 在 `.skills/` 目录下创建新文件夹
2. 编写 `SKILL.md` 文件
3. 在 Agent 面板中选择该 Skill

## 📝 会话管理

### 会话列表

按时间分组显示：
- 今天
- 昨天
- 更早

### 会话操作

| 操作 | 说明 |
|------|------|
| **重命名** | 行内编辑会话名称 |
| **删除** | 删除会话（确认弹窗防止误操作） |
| **切换版本** | 对同一问题切换不同的 AI 回复版本 |

### 消息特性

- **流式响应**：实时显示 AI 回复
- **思考模式**：展示 AI 的推理过程（Chain of Thought）
- **工具调用可视化**：展开/折叠显示工具调用详情
- **实体链接卡片**：工具产生的链接以卡片形式展示

## 🔒 权限与安全

### 工具权限控制

- 每个 Agent 只能调用被授权的工具
- 未授权的工具即使 AI 想调用也会被拒绝
- 系统工具（如 `test_echo`）默认对所有 Agent 可用

### 文件操作边界

- Agent 只能操作 `posts`、`knowledge`、`resources` 板块
- `about` 板块受保护，AI 无法修改
- 所有文件操作都有路径遍历防护

## 🚀 高级用法

### 让 Agent 自动创建文章

```
用户：帮我写一篇关于 Docker 的入门教程

Agent（写作专家）:
1. 调用 web_search 搜索 Docker 最新信息
2. 调用 create_article 创建文章
3. 文章保存到 docs/sections/posts/docker-guide.md
4. 自动触发 Git 提交
```

### 多 Agent 协作

```
Agent A（研究助手）：搜索并整理资料
    ↓
Agent B（写作专家）：基于资料撰写文章
    ↓
Agent C（编辑）：审核并优化文章
```

> 目前多 Agent 协作需要手动切换，未来版本将支持自动调度。
