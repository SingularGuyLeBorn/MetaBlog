## 飞书文档工具全量支持 URL 提取 document_id

### 问题发现
用户反馈：`feishuDocMeta` 传完整飞书链接没有反应(没效果),只有 `feishuDocRead` 能正常工作. 

### 根因分析
之前只给 `feishuDocRead` 加了 `extractDocumentId()` 函数,其他工具(`feishuDocMeta`/`feishuDocBlocks`/`feishuDocAppend`/`feishuDocUpdateBlock`/`feishuDocDeleteBlock`)仍然直接拿 `document_id` 去调 API. 传完整链接时,后端收到的 document_id 是 `https://xxx.feishu.cn/docx/AbCdEfGh`,飞书 API 不认识这个格式,直接返回文档不存在的错误. 

### 方案选择
- ✅ 方案 A：给所有用到 `document_id` 的 executor 都加上 `extractDocumentId()` — 最小改动,直接解决问题
- ❌ 方案 B：在后端统一做 URL 提取 — 虽然也可以,但前端 tool definition 里描述写的是"文档 ID",LLM 看到失败信息后可能仍然不明白为什么传链接不行,前端同步改 description 更友好

### 实现过程
1. **把 `extractDocumentId` 提到文件顶部**(第8行),所有 executor 共享,避免重复定义
2. **批量修改所有 Definition**：description 加上"支持传入完整飞书文档链接",参数说明从"文档 ID"改为"文档 ID 或完整飞书文档链接"
3. **批量修改所有 Executor**：
   - `feishuDocRead` — 已有,确认正常
   - `feishuDocMeta` — 添加 `extractDocumentId`,错误提示补全
   - `feishuDocBlocks` — 添加 `extractDocumentId`,错误提示补全
   - `feishuDocAppend` — 添加 `extractDocumentId`,body 里用 `docId`
   - `feishuDocUpdateBlock` — 添加 `extractDocumentId`,payload 里用 `docId`
   - `feishuDocDeleteBlock` — 添加 `extractDocumentId`,body 里用 `docId`
4. **删除旧的 `extractDocumentId` 函数副本**(原在文件后部第197-206行),修复 TS2393 duplicate function implementation 编译错误
5. **补漏**：`feishuDocBlocks` 和 `feishuDocUpdateBlock` 的 executor 在前一轮批量替换中未命中,单独再修一次

### 修改文件清单
| 文件 | 修改类型 | 说明 |
|------|----------|------|
| `src/theme/tools/lark/doc.ts` | 修改 | 全量支持 URL 提取,删除重复函数,修复 TS 编译错误 |

### 验证结果
- `npx tsc --noEmit` 无 doc.ts 相关错误 ✅
- 所有 6 个读/写/删工具均支持 `https://xxx.feishu.cn/docx/AbCdEfGh` 格式链接

### 是否复发
旧问题已根治. 所有 executor 统一走 `extractDocumentId`,不会再出现某个工具漏改的情况.

- 部分思考过程丢失
- 某些细节决策可能只保留了结论,没有保留推理过程
- 压缩后的 summary 可能遗漏了某些关键约束

这可能导致我在后续轮次中：
- 重复之前已经排除过的方案
- 忽略之前已经确认过的约束
- 对代码状态的理解与实际情况有偏差

### 根因分析(前端交互问题)
用户在描述前端聊天界面的发送机制：
- **发送方式 1**：直接点击发送按钮

- **问题**：当 AI 正在处理(上一轮对话未结束)时,界面未禁用发送按钮,用户可能误触发送新消息
- **建议**：增加状态锁 — 当 AI 处理中(pending/running)时,禁止通过按钮发送新消息

- 我给出的回答与之前的决策不一致？
- 我重复了之前已经做过的工作？
- 我遗漏了之前确认过的约束？
- 代码修改与之前的意图不符？

## 表格内公式渲染修复

### 问题发现
用户反馈表格内公式渲染异常,提供两个截图：
1. 飞书文档中表格公式被拆分/换行(如 `$\text{KL}(\pi_{\text{ref}})$` 被拆成多行)
2. Chat 界面中表格公式列错位(如 `$Q(y|x)$` 被拆到不同列)

### 根因分析
**问题 1：`|` 管道符灾难**(核心问题)
Markdown 表格语法使用 `|` 作为列分隔符. 公式如 `$Q(y|x)$`、`$D_{KL}(P \| Q)$` 中的 `|` 被 `splitTableCells` 和 `marked` 的 GFM 表格解析器当作列分隔符,导致：
- 后端：`$Q(y` 和 `x)$` 被拆到两个不同单元格
- 前端：`marked.parse` 同样将公式拆到错误的表格列

**问题 2：公式末尾 `\\` 导致 LaTeX 换行**
AI 生成的 Markdown 中公式末尾常带 `\\`(如 `$\text{KL}(\pi_{\text{ref}})\\`). LaTeX 中 `\\` 是换行命令,飞书 table cell 中的 equation 元素会将其解释为换行,导致公式被强制换行显示. 

### 方案选择
- ✅ 重写 `splitTableCells`：状态机解析,保护 `$...$` / `$$...$$` 公式内的 `|`,同时支持 `\|` 转义
- ✅ table cell 中 equation 降级：包含 `\\` 的 equation 降级为普通 text_run(用 `\(...\)` 包裹),避免 LaTeX 换行
- ✅ 前端 MessageBubble 预处理：在 `marked.parse` 前将表格行公式中的 `|` 替换为 `\vert`
- ✅ SKILL.md 增加表格公式专门约束章节

### 实现过程

#### 1. 后端 splitTableCells 重写

- 新增状态机解析逻辑：遍历字符,遇到 `$` 进入公式保护模式,公式内的 `|` 不参与 split
- 支持 Markdown 标准 `\|` 转义序列

#### 2. table cell equation 降级
`src/theme/tools/lark/markdown-to-blocks.ts`：
- 新增 `sanitizeTableCellEquations` 函数
- 包含 `\\` 的 equation 降级为 text_run：去掉末尾 `\\`,内部 `\\` 替换为空格,用 `\(...\)` 包裹
- 在 `parseMarkdownTable` 中对所有 cell content 应用此清理

#### 3. 前端 MessageBubble 预处理
`src/theme/components/ai-chat/MessageBubble.vue`：

#### 4. SKILL.md 约束增强

## 交互 3：添加一键 OAuth 获取 user_access_token

### 问题发现
用户运行 notebook Wiki 相关 cell 时报错 `99991677: Authentication token expired`,需要获取新的 `user_access_token`. 
用户询问"哪里？"——不知道 API 调试台入口在哪里. 

### 根因分析
- `user_access_token` 有效期约 2 小时,过期后 Wiki API(create_wiki_space、move_wiki_node 等)会报错
- 飞书开放平台没有明显的"一键获取 token"按钮,需要通过 OAuth 授权流程获取
- 手动去 API 调试台复制 token 对非开发者不够友好

### 方案选择
| 方案 | 描述 | 优劣 |
|------|------|------|
| A：手动去 API 调试台 | 用户自己找入口、复制粘贴 | ❌ 入口隐蔽,用户体验差 |
| B：notebook 内一键 OAuth(推荐)| 运行 cell → 点击链接 → 扫码 → token 自动写入 | ✅ 用户友好,可复用 |
| C：后端服务常驻刷新 | 在服务器端维护 token 刷新逻辑 | ❌ 过度设计,当前只是 notebook 实验 |

选择 **方案 B**：在 notebook 中添加一个 cell,启动本地 HTTP 服务器,通过飞书 OAuth 授权流程自动获取 token. 

### 实现过程

**1. feishu_client.py 新增 `authorize_user()` 方法**
- 导入：`secrets`、`threading`、`webbrowser`、`http.server`
- 方法功能：
  - 生成随机 state + 飞书授权 URL
  - 启动 `HTTPServer` 监听 `127.0.0.1:8088`
  - 打印授权链接,尝试自动打开浏览器
  - 用户扫码授权后,飞书重定向到 `localhost:8088/?code=xxx&state=xxx`
  - 服务器用 code 调用 `/authen/v2/oauth/token` 换取 token
  - 返回 HTML 成功页面,自动更新 `client.user_access_token`
- 超时机制：默认 120s,超时给出排查建议

**2. Notebook 插入新 cell(环境初始化之后、用户搜索之前)**
- Markdown cell：说明前提条件(安全设置中添加重定向 URL)
- Code cell：检查已有 token → 无则调用 `client.authorize_user()` → 成功后更新 `os.environ` 和 `client.user_access_token`
