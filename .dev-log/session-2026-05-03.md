## 任务 4：封装飞书 Token 管理工具链(热更新 + 自动刷新 + 错误码翻译)

### 问题发现
1. `user_access_token` 存在 `.env` 里,进程启动后不再重新加载,刷新 token 后必须**重启服务**才能生效
2. 后端没有自动刷新 `user_access_token` 的机制,每次过期只能手动改 `.env`
3. 错误码 `99991677`(token 过期)和 `99991679`(scope 不足)没有友好的翻译和自动处理
4. 大模型无法主动判断 token 状态,也无法主动刷新
5. Skill 文档缺少完整的重新授权流程说明

### 根因分析
- `.env` 是静态配置,Node.js 进程只在启动时读取一次 `process.env`
- 刷新 token 后写入 `.env`,但运行中的进程看不到变化
- 需要把 token 从 `.env` 迁移到独立的 JSON 缓存文件,实现"热更新"

### 方案选择
| 方案 | 说明 | 结果 |
|------|------|------|
| A. 定时轮询 `.env` | 每秒检查 `.env` 修改时间,有变化重新读取 | ❌ 性能差,不优雅 |
| B. **独立 JSON 缓存文件**(选中) | token 存在 `~/.feishu_oauth_{app_id}.json`,每次调用前从文件读取 | ✅ 零性能开销,天然热更新 |
| C. IPC/消息通知 | 刷新 token 后发送 IPC 消息通知主进程 | ❌ 过于复杂 |

### 实现过程

**1. 新增后端服务** `server/services/lark-token-manager.ts`
- `getUserAccessToken()`：从 JSON 缓存文件读取 → 检查过期(预留 5 分钟缓冲)→ 自动刷新 → 写回文件 → 返回有效 token
- `getTokenStatus()`：返回 token 状态(是否存在、过期时间、refresh_token 状态)
- `refreshTokenManually()`：手动刷新接口
- `RefreshTokenExpiredError`：自定义错误,refresh_token 失效时抛出
- 内存缓存 5 秒 TTL,减少高频文件读取

**2. 修改后端路由** `server/routes/external/lark.ts`
- `getUserAccessToken()` 改为异步,内部调用 TokenManager
- `feishuApi()` / `feishuApiMultipart()` 的 user token 判断逻辑改为检查缓存文件是否存在(而非 `larkEnv.userAccessToken`)
- 新增路由：`POST /api/lark/token/refresh`、`GET /api/lark/token/status`

**3. 新增前端工具** `src/theme/tools/lark/token.ts`
- `feishuTokenRefresh` / `feishuTokenRefreshDef`：手动刷新 token
- `feishuTokenStatus` / `feishuTokenStatusDef`：查询 token 状态

**4. 注册工具** `src/theme/tools/index.ts`
- 导入并注册 `feishuTokenRefresh`、`feishuTokenStatus`

**5. 更新错误翻译** `server/utils/lark-error-translator.ts`
- 新增 `99991677`(token 过期)→ "后端会自动尝试刷新,如果失败则调用 feishuTokenRefresh"

## 任务 2：集成 Piper TTS + Whisper 本地 ASR 语音服务

### 问题发现
用户询问最轻量级且免费的 TTS/ASR 方案，澄清 Edge-TTS（免费但非官方不稳定）和 Whisper API（付费）后，明确要求将 **Piper（本地 TTS）+ Whisper Tiny 本地版（ASR）** 集成到项目中。

### 根因分析
项目中已有 OCR 服务通过 `child_process.spawn` 调用本地 Python 二进制文件的成功先例（`server/services/ocr.ts`），语音服务可以复用同一架构模式。前端类型系统已支持 `audio` 附件类型，但服务端无任何语音处理代码。

### 方案选择

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **Piper + whisper.cpp 本地调用** | 完全离线、零费用、磁盘 <100MB、复用现有 spawn 架构 | 需要用户下载二进制和模型文件 | ✅ **选定** |
| Edge-TTS + OpenAI Whisper API | 无需本地模型、语音质量高 | Edge-TTS 非官方随时失效；Whisper API 按量付费 | ❌ 不满足"免费+稳定"要求 |
| FunASR + MeloTTS Python 服务 | 中文效果最佳 | 需要 Python 环境常驻，违背"轻量"初衷 | ❌ 过重 |

**失败方案记录**：曾考虑让 TTS 直接返回 Base64 JSON，但短文本产生的音频可能几十 KB，Base64 膨胀 33% 后前端data URL播放有兼容性问题；最终路由层保留 `format=stream` 默认返回 `audio/wav` 流，`format=json` 可选返回 Base64，兼顾播放器直接播放和前端灵活处理。

### 实现过程
1. **创建 `server/services/tts.ts`** — Piper 封装服务

2. **创建 `server/services/asr.ts`** — whisper.cpp 封装服务

   - 识别完成后自动清理 `.wav.json` 临时文件
   - 超时保护 120 秒，最大音频 50MB

3. **创建 `server/routes/internal/voice.ts`** — REST API 路由
   - `POST /api/tts`：接收 `{ text, format? }`，默认返回 `audio/wav` 流，可选 `format=json` 返回 Base64

   - `GET /api/voice/status`：检测 Piper 和 Whisper 可执行文件及模型可用性

## 任务 3：Piper + Whisper 本地测试与修复

### 问题发现
用户要求先在 `project/experiments/voice-test/` 下本地测试 Piper TTS 和 Whisper ASR 是否正常工作，再集成进系统。测试过程中暴露多个问题：

1. **PowerShell 脚本编码问题**：`.ps1` 文件用 UTF-8 without BOM 保存，PowerShell 解析时中文字符乱码导致语法错误
2. **GitHub 下载问题**：`ggerganov/whisper.cpp` 已迁移到 `ggml-org/whisper.cpp`，旧 release URL 返回 404
3. **zip 解压路径问题**：Piper 的 zip 解压后文件嵌套在 `piper/piper/` 子目录中
4. **`shell: true` 路径空格问题**：Windows 下 `spawn(path, args, { shell: true })` 遇到含空格的路径（如 `D:\ALL IN AI\...`）会把参数截断，导致 Piper/Whisper 启动失败
5. **curl 下载 zip 损坏**：curl 下载 GitHub release zip 后 `Expand-Archive` 报"中央目录损坏"，改用 `Invoke-WebRequest` 才成功

### 根因分析
- PowerShell 5.x 默认按系统编码（GBK）读取无 BOM 的 UTF-8 脚本，中文被误解析为乱码，破坏括号匹配
- whisper.cpp 项目所有权从 `ggerganov` 迁移到 `ggml-org`，release URL 变了但文档未同步更新
- `shell: true` 把参数拼接成命令行字符串再交给 cmd.exe 解析，路径中的空格被当作参数分隔符

### 方案选择
| 问题 | 尝试方案 | 结果 |
|------|---------|------|
| PS 编码 | 用 `Out-File -Encoding utf8BOM` | PowerShell 5 不支持 `utf8BOM` 参数，失败 |
| PS 编码 | 用 `[System.IO.File]::WriteAllText(path, text, New-Object UTF8Encoding $true)` | ✅ 成功写入带 BOM 的 UTF-8 |
| 下载 zip | curl.exe 下载 | 返回 HTML 错误页面或损坏 zip，失败 |
| 下载 zip | `Invoke-WebRequest` 下载 | ✅ 成功，但发现旧 URL 404 |
| 空格路径 | `{ shell: true }` | ❌ 参数截断 |
| 空格路径 | `{ shell: false }`（默认） | ✅ Node.js `spawn` 内部自动处理含空格路径 |

### 实现过程
1. **清理并重新下载**：手动整理 `tools/piper/` 和 `tools/whisper/` 目录结构
   - Piper exe 和全部依赖从 `tools/piper/piper/` 提到 `tools/piper/`
   - Whisper 用正确的 `ggml-org/whisper.cpp/releases/download/v1.8.4/whisper-bin-x64.zip` 重新下载
2. **修复 `server/services/tts.ts`**：移除 `shell: process.platform === "win32"`
3. **修复 `server/services/asr.ts`**：移除 `shell: process.platform === "win32"`
4. **更新 `.env.example`**：Whisper 下载注释更新为 `ggml-org/whisper.cpp`
5. **删除有问题的脚本**：`download-voice-models.ps1`（编码问题 + 地址过期）

## 任务 4：前端 Chat 界面语音功能集成

### 问题发现
用户要求在前端 Chat 界面接入语音输入（按住说话 → ASR）和 TTS 朗读（AI 消息播放语音）。此前服务端 API 已就绪，但前端无任何语音相关代码。

### 根因分析
前端 chat 组件架构清晰：
- `ChatInput.vue` 负责输入和附件，通过 `emit('send')` 向上传递消息
- `MessageBubble.vue` 负责消息渲染，AI 消息已有操作按钮栏（复制、重新生成）
- 浏览器原生 `MediaRecorder` API 可实现录音，`<audio>` 元素可播放 TTS 返回的流

### 方案选择
| 功能 | 方案 | 决策 |
|------|------|------|
| 录音 | `MediaRecorder` + `getUserMedia` | ✅ 原生 API，无需额外库 |
| 录音格式 | webm(opus) → 上传 `/api/asr` | ✅ 后端已支持 webm，Chrome/Edge 完美兼容 |
| TTS 播放 | `fetch('/api/tts')` → `response.blob()` → `URL.createObjectURL()` → `<audio>` | ✅ 流式播放，无需等文件落地 |
| 状态管理 | 新增 `useVoice.ts` composable | ✅ 录音/ASR/TTS 统一封装，组件层只关心调用 |

### 实现过程
1. **新增 `src/theme/composables/useVoice.ts`**
   - `startRecording()` / `stopRecording()`：封装 `MediaRecorder`，自动释放麦克风
   - `transcribeAudio(blob)`：multipart 上传 `/api/asr`，返回识别文本
   - `speak(text)` / `stopSpeaking()`：调用 `/api/tts`，用 `<audio>` 播放返回的 WAV 流
   - 统一 `status: 'idle' | 'recording' | 'transcribing' | 'speaking'` 状态

2. **新增 SVG 图标 `src/theme/components/common/Icon.vue`**
   - `mic`：麦克风图标
   - `volume-2`：喇叭图标

3. **修改 `ChatInput.vue`**
   - 输入框左侧新增语音按钮（点击开始录音，再次点击停止并识别）
   - 录音中按钮红色 pulse 动画，识别中按钮橙色 loading
   - 识别结果自动追加到输入框末尾
   - 底部提示增加 `Mic 语音` 说明

4. **修改 `MessageBubble.vue`**
   - AI 消息操作栏新增"朗读"按钮（在"复制"按钮左侧）
   - 点击调用 `speak()` 播放消息内容
   - 播放中按钮黄色 pulse 动画，文字变为"停止"

5. **样式**：`.voice-btn-3d` 与 `.attach-btn-3d` 风格一致，`.action-btn.speaking` 与 `.action-btn.copied` 风格一致

### 修改文件清单
| 文件 | 修改类型 | 说明 |
|------|---------|------|
| `src/theme/composables/useVoice.ts` | 新增 | 录音+ASR+TTS 统一封装 |
