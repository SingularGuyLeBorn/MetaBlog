## 任务 4：封装飞书 Token 管理工具链（热更新 + 自动刷新 + 错误码翻译）

### 问题发现
1. `user_access_token` 存在 `.env` 里，进程启动后不再重新加载，刷新 token 后必须**重启服务**才能生效
2. 后端没有自动刷新 `user_access_token` 的机制，每次过期只能手动改 `.env`
3. 错误码 `99991677`（token 过期）和 `99991679`（scope 不足）没有友好的翻译和自动处理
4. 大模型无法主动判断 token 状态，也无法主动刷新
5. Skill 文档缺少完整的重新授权流程说明

### 根因分析
- `.env` 是静态配置，Node.js 进程只在启动时读取一次 `process.env`
- 刷新 token 后写入 `.env`，但运行中的进程看不到变化
- 需要把 token 从 `.env` 迁移到独立的 JSON 缓存文件，实现"热更新"

### 方案选择
| 方案 | 说明 | 结果 |
|------|------|------|
| A. 定时轮询 `.env` | 每秒检查 `.env` 修改时间，有变化重新读取 | ❌ 性能差，不优雅 |
| B. **独立 JSON 缓存文件**（选中） | token 存在 `~/.feishu_oauth_{app_id}.json`，每次调用前从文件读取 | ✅ 零性能开销，天然热更新 |
| C. IPC/消息通知 | 刷新 token 后发送 IPC 消息通知主进程 | ❌ 过于复杂 |

### 实现过程

**1. 新增后端服务** `server/services/lark-token-manager.ts`
- `getUserAccessToken()`：从 JSON 缓存文件读取 → 检查过期（预留 5 分钟缓冲）→ 自动刷新 → 写回文件 → 返回有效 token
- `getTokenStatus()`：返回 token 状态（是否存在、过期时间、refresh_token 状态）
- `refreshTokenManually()`：手动刷新接口
- `RefreshTokenExpiredError`：自定义错误，refresh_token 失效时抛出
- 内存缓存 5 秒 TTL，减少高频文件读取

**2. 修改后端路由** `server/routes/external/lark.ts`
- `getUserAccessToken()` 改为异步，内部调用 TokenManager
- `feishuApi()` / `feishuApiMultipart()` 的 user token 判断逻辑改为检查缓存文件是否存在（而非 `larkEnv.userAccessToken`）
- 新增路由：`POST /api/lark/token/refresh`、`GET /api/lark/token/status`

**3. 新增前端工具** `src/theme/tools/lark/token.ts`
- `feishuTokenRefresh` / `feishuTokenRefreshDef`：手动刷新 token
- `feishuTokenStatus` / `feishuTokenStatusDef`：查询 token 状态

**4. 注册工具** `src/theme/tools/index.ts`
- 导入并注册 `feishuTokenRefresh`、`feishuTokenStatus`

**5. 更新错误翻译** `server/utils/lark-error-translator.ts`

## 修复：Wiki 卡片显示 + Doc 追加内容失败 1770032

## 飞书文档表格自动列宽

### 方案选择
| 方案 | 说明 | 选择 |
|------|------|------|
| A. 固定宽度 | 每列固定 150px | ❌ 无法适配不同内容 |
| B. 按内容估算 | 根据每列最长单元格的字符数计算宽度 | ✅ 最自然 |
| C. Markdown 扩展语法 | 支持 `| 列名 {width=200} |` | ❌ 过度设计，AI 不会用 |

**选择 B**：根据表头和数据行中每列最长内容的字符数，估算渲染宽度（中文 14px/字，英文 8px/字，加 32px padding），限制在 [60, 500] px。

### 实现过程
在 `markdown-to-blocks.ts` 中新增两个函数：

1. `estimateTextWidth(text)` — 估算单段文本的渲染宽度
2. `estimateColumnWidths(lines, colCount)` — 取每列所有单元格的最大估算宽度

修改 `parseMarkdownTable()`，在返回的 `table.property` 中加入 `column_width`：

```typescript
const columnWidths = estimateColumnWidths(lines, colCount)
return {
  block_type: 31,
  table: {
    property: {
      column_size: colCount,
      row_size: rowCount,
      column_width: columnWidths,  // ← 新增
    },
  },
  _cell_contents: cellContents,
}
```
