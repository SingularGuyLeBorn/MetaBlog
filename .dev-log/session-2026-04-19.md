## 任务 1：飞书 Table Cell 创建 API 探测(Python Lab)

### 问题发现
- 之前的 `markdown-to-blocks.ts` 把 table cell 作为 `children` 嵌套在 table block 下，POST 到飞书 API 失败：
  - `1770028`: block not support create children(table 不支持 children API)
  - `1770029`: block not support to create(table_cell 不能直接创建)
- 需要找到正确的多步创建流程

### 根因分析
飞书 table (block_type: 31) 的创建机制是：
1. POST table block 只带 `property` → 飞书**自动生成**空 cell blocks
2. 返回 `table.cells` 数组(行优先排列的 cell block_id)
3. table 本身不支持 `children` API，table_cell 不支持直接创建

### 方案选择
| 方案 | 说明 | 结果 |
|------|------|------|
| A. PATCH cell 更新 `table_cell.elements` | 最直觉的方案 | ❌ 全部返回 `1770001 invalid param` |
| B. POST children 到 table | 尝试绕过限制 | ❌ `1770028` |
| C. POST children 到 table_cell | 利用 cell 的 children API | ✅ **成功！** |
| D. blocks/convert API | 用 Markdown→Blocks 转换 | ❌ 需要 `docx:document.block:convert` 权限，未开通 |
| E. batch_update | 批量更新接口 | ❌ `1770001`，和单条 PATCH 一样 |

### 关键发现(必须记录)

#### 发现 1：PATCH 完全不可用(不是格式问题！)
尝试了**所有可能的 PATCH body 格式**，全部返回 `1770001`：
- 精确复用 GET 返回的结构
- 不带 `text_element_style`
- 带 `style: {}`
- 带 `replace_all: true`
- 用 `batch_update`(各种 request_type 组合)
- 用实际 `revision_id`(而非 `-1`)
- 用 urllib(排除 requests 库问题)
- JSON Patch 格式 (RFC 6902) → 返回 `9499 Bad Request`
- v2 API → 404

**结论**：当前应用的 tenant_access_token **没有 PATCH 权限**(但错误码是 1770001 而非 99991672，说明端点可访问，参数校验层就拦截了)。

#### 发现 2：DELETE 也完全不可用
所有 DELETE 尝试返回 `404 page not found`：
- `DELETE /blocks/{block_id}`
- `DELETE /blocks/{parent_id}/children?start_index=...`
- `POST /blocks/batch_delete`

**结论**：当前应用没有删除块的权限/端点。

#### 发现 3：POST children 到 cell 是可行的 workaround
```python
POST /docx/v1/documents/{doc_id}/blocks/{cell_id}/children
{
  "children": [{
    "block_type": 2,
    "text": {
      "elements": [{"text_run": {"content": "单元格内容"}}]
    }
  }]
}
# → code: 0，成功创建 text child
```

**副作用**：每个 cell 已经有一个飞书自动生成的空 text child(content: `""`)，POST 后会变成两个 children。raw_content 验证显示空 child 会渲染为一个空行。

#### 发现 4：cell 的 GET 结构
```json
{
  "block_id": "...",
  "block_type": 32,
  "children": ["doxcnxxx..."],
  "parent_id": "...",
  "table_cell": {}
}
```
- `table_cell` 是空的 `{}`
- 内容存储在 `children[0]`(一个 text block)中

## 任务 2：TypeScript 端改造 ✅ 已完成

### 实现过程
1. **修改 `parseMarkdownTable`**(`src/theme/tools/lark/markdown-to-blocks.ts`)
   - 旧逻辑：生成 `children: [table_cell blocks]`，每个 cell 是一个 `block_type: 32` 的嵌套块
   - 新逻辑：生成 `_cell_contents: TextElement[][]`，行优先扁平数组，每个元素是一个 cell 的 `elements` 数组
   - `mergeBlockTextElements` 无需修改，因为 table block 的 `table` 字段没有 `elements` 数组，函数会自然跳过

2. **重写 `createTableBlock`**(`server/routes/lark.ts`)
   - 旧逻辑(三步，全部失败)：
     1. POST 空 table
     2. POST cell blocks 到 table children → `1770028`
     3. PATCH 更新 table.cells → `1770001`
   - 新逻辑(两步，基于实测)：
     1. POST 空 table(只含 `property`)→ 飞书返回 `table_id` + `cell_ids`
     2. 遍历 `cell_ids`，对每个 cell POST text block child(`block_type: 2`)
   - 增加 QPS 保护：每 3 个 cell POST 后延时 400ms
   - 增加空 cell 跳过：如果 cell 内容没有任何 `text_run.content` 或 `equation.content`，跳过 POST
   - 增加长度校验：`cell_contents.length === cell_ids.length`

3. **更新 append 路由的 table 检测条件**
   - 旧：`block.block_type === 31 && Array.isArray(block.children)`
   - 新：`block.block_type === 31 && Array.isArray(block._cell_contents)`

### 关键代码(createTableBlock)
```typescript
async function createTableBlock(documentId: string, tableBlock: any): Promise<any> {
  const cellContents: any[][] = tableBlock._cell_contents || [];
  const { _cell_contents: _, ...tableData } = tableBlock;

  // 1. 创建空 table
  const tableResult = await feishuApi("POST", `/docx/v1/documents/${documentId}/blocks/${documentId}/children`, { children: [tableData] });
  const tableId = tableResult.data?.children?.[0]?.block_id;
  const cellIds: string[] = tableResult.data?.children?.[0]?.table?.cells || [];

  // 2. 对每个 cell POST text block
  for (let i = 0; i < cellIds.length; i++) {
    const elements = cellContents[i] || [];
    if (!elements.some((el: any) => el.text_run?.content || el.equation?.content)) continue;
    if (i > 0 && i % 3 === 0) await new Promise((r) => setTimeout(r, 400));
    await feishuApi("POST", `/docx/v1/documents/${documentId}/blocks/${cellIds[i]}/children`, {
      children: [{ block_type: 2, text: { elements } }]
    });
  }
}
```

## 🐛 问题记录：StrReplaceFile 假阳性

### 现象
对 `src/theme/tools/lark/markdown-to-blocks.ts` 第一次调用 `StrReplaceFile` 时，工具返回：
```
File successfully edited. Applied 1 edit(s) with 1 total replacement(s).
```
但随后读取文件发现 `parseMarkdownTable` **完全没有被修改**，仍然是旧代码(`children: cellBlocks`)。

### 根因分析
`StrReplaceFile` 的 `old` 参数与文件中的实际内容**不完全匹配**(可能是空白字符、换行符或不可见字符的微小差异)，导致替换操作实际上没有找到匹配项。但工具仍然返回了 "success"，这是一个**假阳性**。

### 解决方案
- 第二次调用时，使用 `ReadFile` 精确读取文件的实际内容，然后基于实际内容进行 `StrReplaceFile`
- 修改后立即用 `tsx` 验证输出格式，确认修改真正生效

## 【修正记录】PATCH/DELETE 实际可用 + Table 创建消除空 child 副作用

> **注意**：以下结论推翻了本日志前半部分"PATCH/DELETE 完全不可用"的错误判断。原因是之前用了错误的 body 格式和路径，而非权限问题。

### 根本原因
- **PATCH 失败**：之前用了 `{"text": {"elements": [...]}}`，飞书实际需要 `{"update_text_elements": {"elements": [...]}}`
- **DELETE 失败**：之前用了 `DELETE /blocks/{block_id}`，飞书实际需要 `DELETE /blocks/{parent_id}/children/batch_delete` + body `{"start_index": N, "end_index": N+1}`

### 实测结果(SDK + direct API 双重验证)

#### PATCH 正确格式
```python
PATCH /docx/v1/documents/{doc_id}/blocks/{block_id}
{"update_text_elements": {"elements": [{"text_run": {"content": "新内容"}}]}}
# → code: 0, msg: success
```
- ✅ text (block_type: 2)
- ✅ heading1~heading9 (block_type: 3~11)
- ✅ bullet (block_type: 12)
- ✅ ordered (block_type: 13)
- ✅ code (block_type: 14)
- ✅ quote (block_type: 15)

#### DELETE 正确路径
```python
DELETE /docx/v1/documents/{doc_id}/blocks/{parent_id}/children/batch_delete
{"start_index": 0, "end_index": 1}
# → code: 0, msg: success
```
- 获取 block 索引：`GET /blocks/{parent_id}/children`
- 返回 `items` 列表，找到目标 block 的 index
- 调用 `batch_delete`

### 消除空 child 副作用(Table 创建最终方案)

**旧方案(有副作用)**：创建空 table → 对每个 cell POST text block child → 每个 cell 两个 children(一个空 + 一个内容)→ raw_content 有空行

**新方案(无副作用)**：
1. POST 空 table → 获取 `table_id` + `cell_ids`
2. 对每个 cell：
   a. `GET /blocks/{cell_id}` → 获取 `children[0]`(飞书 auto-generated text block id)
   b. `PATCH /blocks/{text_child_id}` body: `{"update_text_elements": {"elements": [...]}}`
3. raw_content 无空行，每个 cell 只有一个 text block
