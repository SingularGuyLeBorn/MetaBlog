# Step 5: Master Agent 配置者核心 (The Meta-Configurator)

## 1. 概念定位
整个系统的金字塔顶端。
当我们在第四步花了极大精力构建出一个漂亮的“管理中心（UI）”和一套“后端存储与触发机制（API）”后。第五步是在证明“用魔法打败魔法”。
我们把这套“管理中心所有的 API 动作”，打包成 **最高特权指令工具 (System Tools)**，并将他们赋予一个天生具有主宰级别权限的特制大模型助手 —— **Master Agent**。
自此，用户可以彻底抛弃 UI 进行配置，直接发号施令：“帮我建一个助手，每天盯盘查 GitHub 热榜，整理到指定目录下。”——Master Agent 领命后，调用特权 Tool 自动查库、插库、挂载 Trigger、上线该副手。

## 2. 核心功能点与实现状态

### 功能点 1：内置不可抹除的神明级实体
- **描述**：系统中必须有一个 Level 特权标示为 `meta` (或 System) 的实体存在。
- **逻辑限定**：他在所有的“删除”、“编辑”常规后端接口中均被锁死拦截，其物理设定在初始化 `.data/agents.json` 的首位置。
- **实现状态**：🚫 `0% 待实现`

### 功能点 2：专属于神明的高危工具封装 (Master Tools)
- **描述**：我们现有的工具是读写文件或搜索。现在需要“读写Agent设定”的工具。
- **API (供大模型作为 Tool Calling 使用)**:
  - `sys_list_agents` : 返回系统目前所有 Agent 的名称、ID 等摘要状态。
  - `sys_create_agent` : 接受极度庞大的 Schema（含模型选定、提示词、拥有的能力列表、触发器类型）。大模型必须据此推导出合理的配置拼装 json 然后发送系统要求执行。
  - `sys_update_trigger` : 为既定 ID 的 Agent 变更触发方式（比如：大模型收到指令“把小王的工作改成每天十点”，则大模型据此推断小王 ID，且推断 10 点的 Cron 表达式进行调用执行）。
  - `sys_delete_agent` : 执行抹除。
- **实现状态**：🚫 `0% 待实现`。这是 Step 5 代码层最硬核的部分，极大考验你写的 Schema 描述能否让 Deepseek 完全理解不瞎调。

### 功能点 3：专属对话终端与常驻唤起区 (Dock Interface)
- **描述**：它不能和其他“干苦工”的普通 Agent 混杂在一起。应该享有特殊的权限 UI。只要你不彻底将其休眠关闭，它的指示灯或通讯窗口应始终能够随叫随到地浮于应用极左或极右下角的特殊Dock。
- **UI交互**：
  - 常态下，在侧变沿或右侧提供一个有异色高光特效的悬浮按钮。
  - 展开为一个简洁精悍的面板。
  - 会话必须长期保活（使用长期持久记忆 Context），记住用户对其发出的管理期许。
- **实现状态**：🚫 `0% 待实现`

### 功能点 4：指令下达与副作用显现 (Action Visualization)
- **描述**：当他在大模型后台把新副手建立完成后，应该让用户具有直接感知。
- **UI交互**：Master Agent 发言：“已为您创立「GitHub巡查员」，他会在明早八点首次执行。” 在对话气泡下方，应直接注入一个 `[打开新Agent设置核验]` 或 `[立即查验档案馆]` 的交互按卡片。
- **实现状态**：🚫 `0% 待实现`。

## 3. 该阶段研发时序与期望流转
此步骤位于全开发生命周期尾声，其前提是 **第四步中的功能已 100% 毫无 bug 地运行且 API 层高度稳定**，否则大模型通过 Tool 去调后端建 Agent 极大概率写入脏数据导致整个系统雪崩。

| 步骤 | 开发行为与关注点 | 研发输入输出要求 |
|---|---|---|
| **I** | 完善后端服务针对这四个特权函数的 `server/routes/...` 调用，且做单元测试级别的容错判定，防止必填项缺失导致崩溃。 | **在服务端补充 `system_management_tools.ts` 并完成调试。** |
| **II** | 将 Master Agent 在初始化脚本中固定注册在 `.data/agents.json` 。将工具硬绑定至该 ID。 | **输出具有 Meta 权限的初始 json 文件配置。** |
| **III** | 前端界面新写一个独立的 `MasterDock.vue` 使用 `useChat` 但锁定 `sessionId: master-0`。挂载全局在 Layout 的顶层。 | **UI 出现在所有路由页面的漂浮层，呼之即来。** |
| **IV** | Vibe Coding：开始直接对话测试，以用户身份施加压力测试，验证其管理其它子系统的准确度。 | **最后呈现出一个可“以语言创造语言应用”的最强形态。** |
