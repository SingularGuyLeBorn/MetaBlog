# Step 4: Agent 管理中心与多智体生态

## 1. 概念定位
在第三阶段解决“具备行事能力的高级 AI”后，“全能神”模式碰壁。我们要把全知全能的超级助手拆解为一群各司其职的专员（Agents）。
Agent 管理中心（档案馆）是为了这群专员打造配置场所。不仅能创造他们、赋予不同的系统提示词、精准配置特定技能和工具，还要制定他们的工作纪律（触发方式：是被动呼叫，还是自动巡逻定时干活）。

## 2. 核心功能点与实现进度

### 功能点 1：顶栏入口与 Agent 隔离会话栈
- **描述**：原 AI 助手不动，另起炉灶。在网页顶栏配置 `Agent 助手` 按钮。
- **UI交互**：点击后进入专有的 Agent Chat 视图（或弹窗）。该视图顶部有明显的 Agent 切换下拉单选。切换后，自动清除对话框，加载对应 Agent 的独立记忆库。在界面某个按钮可直接跳转至管理中心（档案馆）配置。
- **实现状态**：🚫 `0% 待实现`（关键前置工作）。

### 功能点 2：档案馆 UI (AgentAdmin) 与全局信息呈现
- **描述**：用液态玻璃视觉风格，卡片化展示所有的 Agent。
- **UI交互**：打开后置灰全屏，悬浮一层炫酷的配置中心。默认渲染卡片，卡片需即时展示：Agent 名称、模式徽章、所配**工具数/技能数**、**当前状态** (Running/Idle)、**核心运转标签**（定时闹钟或事件监听标）。
- **点击交互**：点击卡片翻转或进入详情 Config 列表。
- **实现状态**：⚠️ `部分实现`（有基础外壳，但缺少状态与触发引擎联动的数据前端展示）。

### 功能点 3：四象限装配车间 (The Configurator)
- **描述**：点进 Agent 后的具体配置面板。支持四种能力的组合。
- **实现状态**：✅ `已完备主要骨架`。
- **操作规则与逻辑**：
  1. **纯提示词模式 (Raw)**: 禁绝所有工具调用，纯聊。
  2. **工具模式 (Tools-Only)**: 用户自行在 Checkbox 里勾选如 `read_file`, `web_search` 等单一工具。
  3. **技能模式 (Skills-Only)**: 技能是多个工具的有逻辑组合包裹，选中某种能力（打包好）。
  4. **混合模式 (Hybrid)**: 选定核心系统技能，再辅修其他个别散装工具（已实现自动去重冲突）。
- **待开发点 (缺失)**：模型下拉选框（目前写死了某个模型）。需允许配不同的 LLM 底座。

### 功能点 4：启动与触发方式配置 (Triggers Engine UI) [核心]
- **描述**：让 Agent 能够“自主”工作。
- **UI交互**：在配置页新开一个 “工作规则” Tab。
  - `被动响应 (Manual)`: 选中则仅在用户呼出聊天框发问时干活。
  - `定时巡航 (Scheduled)`: 选中弹出 Time Picker，最后转为类似 `0 9 * * *` 的 Cron 表达式。
  - `事件激活 (Event Driven)`: 下拉选取系统内事件，例如 `When Article Created 在 /docs/ 下`。
- **实现状态**：🚫 `完全缺失的空窗`。

### 功能点 5：衍生面：Skills 与 Memory 管理
- **描述**：提供复制、导出等运维能力。
- **UI交互**：列表后追加复制、下载按钮。一键克隆相同设定的项，或者把此人的记忆变成 json/md 文件下载以供他用。
- **实现状态**：⚠️ `缺少复制与导出`。

## 3. 后端 API 与底层引擎需求
所有上述保存动作在前端执行完毕（即关闭弹出层时），必须触发 `PATCH /api/agents/update`。

| API / Action | Backend Behavior | Output |
|---|---|---|
| **保存包含触发器配置的 Agent** | HTTP 请求收录到 `.data/agents.json`。 | 返回更新实体 |
| **【隐式组件】Scheduler.ts** | Server 后台程序。监听/扫描 Json 的变化，调用 `node-cron` 注册对应时间点的后台唤醒任务。 | 无 (Side Effect) |
| **【隐式组件】EventBus.ts** | 全局进程监听，收到其它 API 删除/添加文章的 Emit 时，扫描受激 Agent 执行。 | 无 (Side Effect) |

## 4. 期望的实施进度计划
这是整个生态最庞大的一步：
1. **优先**切分顶栏及独立对话视图 (否则做好了没地方用)。
2. **接着**搞定前端那个配置“触发器”的界面与模型选卡，让数据能保存到 Backend API 成功。
3. **其后**在服务端构建真实运转的 Scheduler (Node.js cronjob) 和后台调用链路。
4. **最后**补齐技能与记忆导出的小控件。
